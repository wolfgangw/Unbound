Preset rename keyboard investigation, 2026-10-17

Symptom
Holding a preset name opens its editor with all text selected, but keys do
nothing until an additional real mouse click inside the editor. Internal 024
activated the popout explicitly; 025 forwarded popout window keys with
QCoreApplication::sendEvent. Neither corrected the live Resolve behavior.

Live evidence
Resolve PID 5484 was verified to have internal 025's Unbound.dll loaded.
The fresh passive capture contained 374 records, without truncation. It did
not record typed text. Before the extra click, native focus, Qt focusWidget
and Qt focusObject were already correct; there was no keyboard grabber.
ShortcutOverride and KeyRelease reached the editor after 025's forwarding.
KeyPress did not reach either the probe's application filter for the editor
or its object filter. Selection and cursor remained unchanged. After the
real click, KeyPress reached both filters and text editing worked normally.

This locates the remaining interception in host application dispatch/filtering
before the editor handler. It does not identify a private Resolve function
or prove which internal policy its real-click handling changes.

Change
Keep the handoff restricted to the active Unbound popout, while the visible
rename editor actually has focus. Invoke that owned PresetNameEdit's public
handoff, which calls QLineEdit::event directly. This preserves the Qt editor
and our rename/arrow handlers without sending keys back through host dispatch.
No synthetic clicks, native keyboard hook, Resolve private call or global
shortcut changes are involved. Other windows and ordinary popup interactions
continue through their existing event paths.

Regression
The fixture now models an additional host dispatch interception specifically
for the editor's key presses. With 025's sendEvent forwarding, it fails at
"Left did not collapse selection to the start", matching the reported symptom.
Window-level keys exercise selection collapse, Shift selection, replacement
typing and Enter on an inactive preset, rather than sending directly to the
editor and bypassing the failure. Build checks and fresh Resolve validation
must still be assessed separately: fixtures cannot fully model Resolve.

Internal 2026.10.17.026 completed successfully with the direct-handler change.
The regression passed in both native Windows and offscreen runs, along with
the full build's other required checks. Fresh Resolve confirmation is pending.
