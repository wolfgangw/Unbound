Corner resize crash in internal 2026.10.17.003
=============================================

Evidence
--------
Resolve 21.1.1.0010 crashed at 09:11:10 on 2026-10-17. Its Support/logs
directory contains c14f2a64-2be9-4410-8613-6278072cb014.dmp. Offline analysis
of that minidump and the exact shipped Unbound.dll establishes:

  Exception: 0xc0000005, write to address zero, GUI thread 19988.
  Fault: Unbound.dll + 0x148f8, instruction mov dword ptr [r12], ebx.
  R12 = 0. The filter prologue at +0x145e6 saved R9 (result argument) in R12.
  Native MSG: WM_NCLBUTTONDOWN (0xa1), wParam HTTOPRIGHT (13).
  The callback immediately before the fault had already started resizing.
  The following instruction was the unconditional '*result = 0' store.

The DLL SHA256 is
FFF7A9789940D8E7CA9FD1D26BCB9C18544C999E4948D6C3332596F73FD08AAD.
No live Resolve attach, injected diagnostic, or crash reproduction was needed.

Cause and correction
--------------------
PaneResizeHitFilter ignored Qt's native-event type and assumed every callback
provided a writable result pointer. A dispatcher-level callback can have a null
result. The new filter therefore acted before the window-procedure pass and
then wrote through the null pointer. This is an Unbound bug, not a graphics or
viewer playback failure. The exact event-type string was not recovered from the
dump; the null result and the faulting message are directly established.

The filter now rejects anything other than windows_generic_MSG, and rejects null
message/result pointers before any side effects. Resize initiation remains in
the actual native window-procedure/subclass path with a valid result destination.
Six-pixel edge bands and twelve-pixel corners remain unchanged.

Validation
----------
The native captionless fixture now explicitly supplies all three intercepted
message types with null result pointers and dispatcher event types. These must
pass through without starting a gesture or modifying the result. It also posts
corner presses through Qt's event dispatcher for all four corners, verifies
two-axis resizing, release/capture cleanup, and independent subsequent gestures.
Existing synchronous edge input, cursor, header controls and docking-button
movement checks continue to pass. Native fixtures retain their bounded runner
and cursor-confinement cleanup.

Internal build 2026.10.17.004 contains the correction. A fresh Resolve session
is required for live validation; no running user session was changed or stopped.
