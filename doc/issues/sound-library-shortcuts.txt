Sound Library (Edit, Fairlight): audition activation
==================================================

Related: https://github.com/wolfgangw/Unbound/issues/2

Status: Edit fix validated in the normal internal Windows build. Fairlight's
targeted live correction also restores normal behavior and is now integrated;
fresh-session production validation remains pending. macOS validation pending.

When docked, clicking Sound Library selects its audition player for J/K/L, Space
and I/O. When floating, those shortcuts instead affect the timeline. Passive
tracing establishes that Qt focus is correctly in the Sound Library results list.
Clicking a result activates `m_PlayerPreview`, but the next L shortcut deactivates
that player and activates `widgetEditTimelinePlayer` without moving keyboard focus.
This is command-context routing, not failure to deliver keys or focus the control.

The existing Fairlight audition activation approach was tested with the Edit
Sound Library host. On genuine host activation, it sends one WindowActivate
notification through Resolve's application notify path to main, consuming that
exact event before QWidget activation propagates. Genuine focus then selects the
audition player. It neither forwards keys nor forces focus nor accesses private
memory. The diagnostic preserved Qt focus and active-window identity on every
recorded correction, and shortcuts no longer switched the player to the timeline.

The user reported correct transport/I/O behavior, intuitive Up/Down result
navigation, timeline handoff and docked operation. Logs confirm player activation
and shortcut delivery; visible in/out changes and clip navigation are user checks.

Production reuses `AuditionActivationBridge` with the exact expected host name.
`SidebarFloatSession` binds it before showing either supported Sound Library host,
using `m_PlayerPreview`. Edit uses slot `frameEditPageSoundLibrary` and root
`frameEditPageWidgetsContainer`; Fairlight uses slot
`frameAudioPanelSoundLibraryContainer` and root `WStackPage_Audio`. Fairlight
Media Pool keeps its existing `previewPlayer` binding and audition-header drag.
The shared lifecycle fixture covers all three bindings, manual/startup detachment,
native-slot hiding, page return, nested docking and teardown. Sound Library hosts
remain unparented: no additional ownership or ancestry change is needed.

The isolated diagnostic under `tests/platforms/windows/sound-library-focus/`
supports passive and bridge comparisons in an existing session. The temporary
bridge was disabled before production testing. Internal Windows build
2026.10.22.001 passed the standard build/test/dependency checks; the user then
reported that Edit behaves normally. No settings or shortcut mappings need changing.

Fairlight findings
------------------
Without the correction, Up/Down selects clips but transport shortcuts affect the
main timeline. The audition waveform is missing. Clicking Play advances timecode
without audio, while its overview indicator moves backwards. Docking and selecting
another clip restores the waveform, keyboard audition and Control Room activity.

A Fairlight-only activation bridge, with no parenting or drawing changes, restores
waveforms for newly selected clips and L/K audition playback with normal forward
progress. The trace records native m_PlayerPreview activation after the correction,
with Qt focus and active-window identity unchanged. The user confirmed audible
playback, clip selection, transport keys and timeline handoff all behave normally.
The visual symptoms therefore do not require a separate waveform/layout workaround;
they recover when Resolve selects the proper audition command context.

The diagnostic can now target Fairlight with UNBOUND_FAIRLIGHT_SOUND_LIBRARY=ON
in a separate build directory and uses a distinct DLL identity. An explicit-start
geometry snapshot supports docked/floating comparisons; there is no ongoing widget
discovery. The temporary intervention was stopped before production validation.

Validate the integrated helper in a fresh Resolve session, including startup with
Sound Library floating, page return, dock/refloat, search editing, I/O and J/K/L.
Live aggregate confirmation is not a separately measured pass for every shortcut
or lifecycle case. No private state, synthetic target focus or key interception
is introduced, and Fairlight Media Pool behavior is unchanged.
